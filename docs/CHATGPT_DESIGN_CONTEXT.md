# Контекст проекта «Диплом» (для ChatGPT → бриф дизайна для Cursor)

Скопируйте этот файл в ChatGPT и допишите свои пожелания по дизайну. Попросите модель выдать **структурированное техническое задание по UI/UX**, которое вы потом вставите в Cursor — ассистент сможет менять код по этому описанию.

---

## 1. Назначение продукта

Мобильное приложение **«Учёт посещаемости»**: расписание, журнал посещаемости, оценки, уведомления, NFC; роли студент / преподаватель / администратор.

---

## 2. Архитектура репозитория

| Модуль | Роль |
|--------|------|
| **`:composeApp`** | Kotlin Multiplatform, **Compose Multiplatform**. Общий UI в `composeApp/src/commonMain/...`. Точка входа UI: `App.kt`, экраны в `.../ui/`. |
| **`:shared`** | Общий код: DTO, репозитории API (Ktor Client), константы, `AuthViewModel`, сообщения об ошибках сети. Android: `BuildConfig.DIPLOM_SERVER_HOST`, эмулятор → хост `10.0.2.2`. |
| **`:server`** | Backend **Ktor**, JWT, H2/PostgreSQL по `application.conf`, REST API под клиент. |

Сборка: Gradle; Android — основная целевая платформа для UI.

---

## 3. Стек UI (важно для дизайна)

- **Jetpack Compose / Compose Multiplatform** + **Material 3** (`MaterialTheme`, `ColorScheme`).
- Тема: **`DiplomTheme`** в `AppTheme.kt` — палитра dark-first (фон `#0B1020`, акценты, типографика sans-serif по сетке из брифа).
- Экран **входа**: `ui/AuthScreen.kt` — mesh-фон, glass-карточка, логотип `FitBrandMark`, градиентная кнопка, версия и язык.
- Локализация частично через **`Strings.kt`** + `AppState.language` (RU / BE / EN) — при смене копирайта дизайн-решения должны учитывать длину строк.
- Навигация: нижняя панель + оверлеи (`OverlayScreen` в `App.kt`): календарь, расписание, админ-центр, посещаемость, оценки, уведомления, NFC-скан.

Основные composable-экраны (файлы в `composeApp/src/commonMain/kotlin/com/example/diplom/ui/`):

- `MainScreen.kt` — домашняя витрина, настройки, выход.
- `ScheduleScreen.kt`, `CalendarScreen.kt`, `AttendanceScreen.kt`, `GradesScreen.kt`, `NotificationsScreen.kt`, `AdminCenterScreen.kt`, `ScanScreen.kt`, `ProfileIdCard.kt` и др.

Платформенные ожидания (`expect`/`actual`): камера, NFC, декод изображений — дизайн не ломать зависимостями от Android-only API в `commonMain`.

---

## 4. Ограничения и ожидания от дизайн-брифа

Просите ChatGPT выдавать не «красивые слова», а **проверяемый бриф для разработчика**, например:

1. **Цвета**: hex для primary / surface / error / фона логина; что берём из `ColorScheme`, что остаётся захардкожено и почему.
2. **Типографика**: какие стили `MaterialTheme.typography` для заголовков, подписей, списков; межстрочные интервалы.
3. **Компоненты**: Card vs Surface, скругления (dp), отступы сетки (4/8/16 dp).
4. **Состояния**: загрузка, ошибка, пустой список — единый паттерн.
5. **Доступность**: контраст, размер зон нажатия.
6. **По экранам**: список изменений по файлам/секциям (логин, главная, расписание…).

```
- … (опиши стиль: минимализм / неоморфизм / бренд вуза / тёмная тема по умолчанию и т.д.)
- … (что не нравится сейчас)
- … (референсы: ссылки или описание)

Задача: сформируй документ для разработчика в Cursor:
1) Краткое видение UI (1 абзац).
2) Дизайн-токены (цвета hex, типографика, скругления, отступы).
3) Правила: логин vs остальное приложение — одна система или намеренный контраст.

Пиши по-русски, без воды, в маркдауне.
```

## 6. Как использовать с Cursor

После ответа ChatGPT вставьте результат в новый чат Cursor и напишите, например: «Сделай UI по этому брифу, не трогай API и бизнес-логику, только `composeApp` и при необходимости `AppTheme.kt` / `Strings.kt`.»

Файл в репозитории: **`docs/CHATGPT_DESIGN_CONTEXT.md`** — при изменении стека или экранов имеет смысл обновить разделы 2–3.
